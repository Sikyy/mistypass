# 能力状态标识规范（2026-04-14）

用于统一文档里“已实现 API 骨架”与“生产可用能力”的口径，避免跨文档语义漂移。

## 1. 标识定义

- `PROD_READY`
  - 含义：可用于生产环境的能力闭环已具备。
  - 最低要求：接口可用、关键回归通过、审计可追溯、失败可观测、无关键外部阻塞。

- `CONTRACT_READY`
  - 含义：API 契约和联调能力已就绪，可做前后端联调或流程验证。
  - 典型状态：`in-memory`、`mock`、或受限通道（例如仅 mock provider）。
  - 约束：不应宣称“生产可用”。

- `SKELETON_ONLY`
  - 含义：仅有模块/数据模型/路由骨架，尚未达到联调验收条件。

- `BLOCKED_EXTERNAL`
  - 含义：能力设计与代码已具备部分条件，但受外部依赖阻塞（资质、第三方账号、硬件等）。

## 2. 标注规则

- 在“当前状态/分阶段计划/能力列表”中，优先在句首添加状态标识。
- 一个能力点仅标注一个主状态；若既可联调又被外部阻塞，以 `CONTRACT_READY` + 说明阻塞为准。
- 若阻塞解除后状态变化，需同步更新对应文档与路线图状态行。

## 3. 示例

- `CONTRACT_READY`：Wallet 告警发送支持 `resend + mock`，可回归可联调。
- `BLOCKED_EXTERNAL`：WhatsApp Meta 企业号真实通道待资质完成。
- `SKELETON_ONLY`：仅完成移动端接口骨架，未覆盖设备侧实机闭环。
